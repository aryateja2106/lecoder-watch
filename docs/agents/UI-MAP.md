**Relay contract.** Refresh always asks the phone while direct machine polls run (`Watch/WatchMeshStore.swift:303`, `Watch/WatchMeshStore.swift:389`). Session output/send/new-session, screen peek, input, volume, clipboard, system, app/display listing and open-URL try the daemon directly when reachable and otherwise send the corresponding `WatchCommand` through the phone (`Watch/WatchMeshStore.swift:568`, `Watch/WatchMeshStore.swift:783`, `Watch/RemoteView.swift:38`). The phone executes those commands in `MeshStore.handle(_:)` (`iOS/MeshStore.swift:1075`); fire-and-forget failures are encoded and surfaced rather than reported as delivered (`docs/product/PRODUCT.md:298`). Relay acknowledgement and receiver wiring are pinned by `scripts/check-relay-ack.swift:3` and `scripts/check-relay-receiver.sh:2`.

## Shared state

| Object | Owns / mutation / persistence |
|---|---|
| `MeshStore` | Phone source of truth for paired machines, polling snapshots, events, capabilities and watch command execution; views call its actions, polling mutates snapshots; tokens/machines use Keychain and preferences/capabilities use `UserDefaults` (`iOS/MeshStore.swift:25`, `iOS/MeshStore.swift:134`, `iOS/MeshStore.swift:168`, `iOS/MeshStore.swift:214`, `iOS/MeshStore.swift:337`). |
| `MeshClient` | Stateless, bearer-authenticated client for one machine; stores only call-local machine/capability configuration and persists nothing (`Shared/MeshClient.swift:5`, `Shared/MeshClient.swift:20`, `Shared/MeshClient.swift:78`, `Shared/MeshClient.swift:97`). |
| `PtyClient` | Phone terminal's live WebSocket, resize, ping and reconnect state; `NativeTerminalScreen` creates/mutates it; memory only (`Shared/PtyClient.swift:10`, `Shared/PtyClient.swift:13`, `iOS/NativeTerminalScreen.swift:143`, `Shared/PtyClient.swift:152`). |
| `TerminalKeyRouter` | Pure byte-to-`/send` translation and streaming modifier folding; native terminal calls it; no state or persistence (`Shared/TerminalKeyRouter.swift:1`, `Shared/TerminalKeyRouter.swift:19`, `Shared/TerminalKeyRouter.swift:29`, `iOS/NativeTerminalScreen.swift:315`). |
| `DaemonCapabilities` | Static list of capability gaps and user-visible symptoms; phone UI reads it; no persistence (advertised capabilities are persisted by `MeshStore`) (`Shared/DaemonCapabilities.swift:35`, `Shared/DaemonCapabilities.swift:45`, `iOS/ContentView.swift:750`, `iOS/MeshStore.swift:214`). |
| `AlertGating` | In-memory reachability cooldown and event dedupe state; `NotificationManager` mutates the gates while its longer-lived alert preferences/history use `UserDefaults` (`Shared/AlertGating.swift:9`, `Shared/AlertGating.swift:45`, `iOS/NotificationManager.swift:53`, `iOS/NotificationManager.swift:63`). |
| `SecureStore` | Keychain wrapper for machine-granting tokens and account sessions; `MeshStore`, `WatchMeshStore` and `LeSearchCloud` mutate it; persists as `AfterFirstUnlockThisDeviceOnly` Keychain items (`Shared/SecureStore.swift:4`, `Shared/SecureStore.swift:11`, `iOS/MeshStore.swift:339`, `Watch/WatchMeshStore.swift:248`, `iOS/LeSearchCloud.swift:153`). |

## The rules this codebase actually follows

| Rule | Evidence |
|---|---|
| Gate every 0.5+ behavior on `/health` capabilities, never version strings; missing/unknown capabilities degrade conservatively. | `Shared/DaemonCapabilities.swift:15`, `Shared/MeshClient.swift:20`, `Shared/MeshClient.swift:29` |
| Auth fails closed: an empty token or missing/malformed bearer is rejected; protected routes pass through the auth gate. | `install/payload/meshd/auth.ts:1`, `install/payload/meshd/auth.ts:21`, `install/payload/meshd/server.ts:1321`; pinned by `scripts/check-mesh-auth.sh:2` |
| Redact every outbound string path before phone, watch, APNs or event storage; the ledger records fingerprints, never values. | `install/payload/meshd/redact.ts:1`, `install/payload/meshd/redact.ts:15`, `install/payload/meshd/server.ts:560`; pinned by `scripts/check-redact.sh:2` |
| Verify by running, not merely building. | `AGENTS.md:21`, `CLAUDE.md:48`; launch checks explain the failure class at `scripts/check-ios-smoke.sh:2` and `scripts/check-watch-smoke.sh:2` |
| Never modify an existing `scripts/check-*` without explicit human approval; adding a new check is the permitted path. | `CLAUDE.md:44`, `docs/factory/CONTRACT.md:25` |
| Every code file must say its purpose in its first comment line; the codemap check enforces the header-derived purpose. | `CLAUDE.md:97`, `scripts/check-codemap.sh:2`, `scripts/check-codemap.sh:11` |

## Where to start for a given task

| Task | Touch/read in this order |
|---|---|
| Add a key the phone can send | `Shared/TerminalKeyRouter.swift:8` → `iOS/NativeTerminalScreen.swift:285` → daemon key vocabulary in `install/payload/meshd/server.ts:49` → `scripts/check-native-terminal-keys.sh:2`; if exposed on watch, also `Watch/WatchViews.swift:1407` and `scripts/check-watch-terminal-wiring.sh:38`. |
| Add a daemon route | Its owning module under `install/payload/meshd/` → the two-line route registration in `install/payload/meshd/server.ts:1303` → `Shared/MeshClient.swift:78` → the calling store/view; keep it capability-gated per `Shared/MeshClient.swift:20` and add a new `scripts/check-*` under the policy at `CLAUDE.md:44`. |
| Change what the watch shows | `Watch/WatchViews.swift:1` for fleet/session screens or `Watch/RemoteView.swift:7` for control → `Watch/WatchMeshStore.swift:522` for state/actions → shared wire types in `Shared/Models.swift:1402` only if the relay contract changes → `iOS/MeshStore.swift:1075` for the phone relay. |
| Add an iPhone screen | Add the view beside its owning flow (`iOS/ContentView.swift:1` for tabs/machines/settings; `iOS/TerminalView.swift:1` for sessions) → add its `NavigationLink`/sheet at the caller → use `MeshStore.client(for:)`, not a bare client, so capabilities travel (`iOS/MeshStore.swift:155`) → add a focused check. |
| Add or change a watch relay command | `Shared/Models.swift:1402` (`WatchCommand`) → watch sender (`Watch/WatchMeshStore.swift:568` or `Watch/RemoteView.swift:38`) → phone handler `iOS/MeshStore.swift:1075` → `scripts/check-relay-ack.swift:3` and `scripts/check-relay-receiver.sh:2`. |
| Add a check | Create a new `scripts/check-*.sh` or `.swift`; do not edit an existing one (`CLAUDE.md:44`) → make the header state what it proves (`scripts/check-codemap.sh:11`) → ensure `scripts/check-all.sh` discovers it (`AGENTS.md:127`). |
