# Security audit — 2026-09-30

**Scope:** the LeSearch Mesh remote-control stack — `meshd`, the `rmux-bridge`, the iOS/Watch
apps, and the installer. **Method:** a full read-through by a dedicated security reviewer plus
live probes against throwaway side-port daemons (never the live `:8899` / `:7820`).

**Verdict:** the `meshd` core is exemplary. The whole HIGH risk came from **one Critical in
the `rmux-bridge`**, now fixed and verified.

---

## Fixed and verified this pass

### CRITICAL — rmux-bridge cross-site WebSocket hijack → keystroke injection (RCE)
`install/payload/rmux-bridge/src/server.ts`

The bridge ships by default, binds `0.0.0.0:7820`, and can type into any mux session, but —
unlike `meshd` — it performed **no Origin/Sec-Fetch check and no Host allowlist**. Any web
page open in a browser on the machine could `ws://127.0.0.1:7820/attach?session=…` and drive a
live shell (loopback is trusted). DNS-rebinding and the cookie path widened it to the LAN.

**Fix:** ported `meshd`'s two guards into the bridge and withdrew loopback trust when a
forwarding header is present:
- `hostAllowed()` → `421` on a foreign `Host` (DNS-rebinding guard).
- `isBrowserCrossSite()` → `401` on any cross-site `Origin` / `Sec-Fetch-Site` (our own
  same-origin WKWebView still passes).
- `authorized()` now ignores loopback trust when `X-Forwarded-For` / `X-Real-IP` / `Forwarded`
  is set (a header can only deny trust, never grant it). `BRIDGE_TRUST_LOOPBACK` semantics kept.

**Verified** (probes on side-port `:8951`):

| probe | before | after |
|-------|--------|-------|
| cross-site WS upgrade (Origin) | `101` (hijacked) | **`401`** |
| cross-site WS upgrade (Sec-Fetch-Site) | `101` | **`401`** |
| foreign `Host` (DNS-rebinding) | `200` | **`421`** |
| proxied loopback (`X-Forwarded-For`) | `200` | **`401`** |
| legit loopback / same-origin | `200` | **`200`** |

`check-bridge-auth.sh`, `check-host-guard.sh`, `check-mesh-auth.sh`, `check-pair-auth.sh` all
green after the change.

### LOW (partial) — constant-time app-key compare
`install/payload/meshd/apps.ts`

The token-free `/a/<slug>-<key>/` path key was compared with `!==` (returns at the first
differing byte → timing side-channel). Now compared with `timingSafeEqual` (`keyEqual`).

## Deferred — with the exact fix, and why it waits

- **MEDIUM — iOS/Watch disable ATS globally** (`project.yml`, `NSAllowsArbitraryLoads: true`).
  The scoped fix is `NSAllowsLocalNetworking`, **but** that risks breaking Tailscale-over-HTTP:
  the CGNAT range `100.64.0.0/10` may not count as "local networking" to iOS, and reaching
  machines over Tailscale is the core feature. Needs a **real-device Tailscale test** before
  flipping. Note: the bearer token travels over plaintext HTTP on the LAN by design — Tailscale
  is the encrypted path; this is a documented design constraint, not a regression.
- **LOW — 32-bit app-path key entropy** (`apps.ts` `KEY` + the serving regex, plus the minting
  site in `install/payload/bin/mesh`). Widen new keys to ≥128 bits and accept `8|32` hex for
  backward compatibility. Spans the CLI generator + a rollout, so it is tracked, not rushed.
- **LOW — Linux `.desktop` `Exec` via `sh -c`** (`input-linux.ts`). Parse `Exec` into argv
  (drop `%f`/`%U` field codes). Deferred: **cannot be verified live** (Pi/Jetson offline), and
  it is defense-in-depth only — an attacker who can write a `.desktop` file already holds the
  token (already RCE).
- **LOW — installer payload not integrity-checked** (`install/install.sh`). HTTPS gives
  transport integrity, but the tarball is extracted and run with no checksum/signature. Publish
  a `sha256` (or minisign) alongside the release and verify before extraction. Release-process
  change.

## Confirmed solid — do not regress (the checks encode these)

`meshd` auth is fail-closed, header-only (no `?token=`), and timing-safe; `hostAllowed` +
`isBrowserCrossSite` + loopback-trust-withdrawal are all present and checked; pairing is
loopback-only mint + single-use code; shell values go through `shq()`/argv (no template-literal
spawn); SQL is parameterized with FTS quoting; `apps.ts`/`files.ts` path handling is jailed
(`resolve` prefix + `realpath`); the session **mirror token** is read-only and narrowed;
redaction + telemetry egress are whitelisted; `SecureStore` uses `AfterFirstUnlockThisDeviceOnly`
Keychain with no plaintext fallback; and the shipped product has **zero third-party
dependencies**. No hardcoded/fallback token anywhere (`testtoken` is gone).
