## Architecture

**Strengths the reviewers want kept:** the single fail-closed constant-time auth gate with
Host/Origin/Sec-Fetch-Site guards (`server.ts:1102-1160, 1283`; `auth.ts`); capability
strings instead of version compares with a check that holds both ends
(`Shared/DaemonCapabilities.swift`, `scripts/check-daemon-gaps.sh`); zero runtime
dependencies down to a hand-written QR encoder with its own decoder check; loopback-minted,
single-use, rate-limited pairing; redaction funnelled through one function before disk,
APNs and Live Activity; comments that record the measured failure and the command that
reproduced it.

Skeptic additions, in severity order:

- **Hosted apps share meshd's origin and inherit the loopback exemption (medium).** An
  agent-built app opened in the Mac's own browser at `http://127.0.0.1:8899/a/…` runs
  same-origin with every API route; its JavaScript can `GET /fs/read?path=~/.mesh/token`
  and `/screen.jpg` and exfiltrate the token. Agent-built code is untrusted by definition.
  Serve `/a/` from a separate port or origin, or add a CSP sandbox and drop the loopback
  exemption for `/fs` and `/screen.jpg`.
- The loopback exemption may buy less than its comment claims: browsers attach `Origin` to
  every non-GET request, so `desktop.html`'s POSTs should already be refused. Verify with a
  real browser; if so, the exemption only serves GETs and MeshDesktop, and narrowing it is
  cheap.
- The bridge cookie is port-blind and script-readable; latent because hosted apps open in
  Safari today. Use an ephemeral per-terminal data store before anyone adds an in-app
  WebView.
