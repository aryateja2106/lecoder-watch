## The Mac had a brain, behind a broken one

`check-brain` asks each machine's own model server for a tool call. The Pi (qwen3:1.7b) and
the Jetson (qwen3:4b) always passed. This Mac failed for a week of runs, and the reason was
ordering, not absence: the probe order is `:8001, :11434, :8080, :1234`, ollama answers on
`:11434`, and the only model installed there is `nl2shell-local` — an 811 MB text fine-tune
that replies

    get_time machine="jetson"

as message content instead of emitting a tool call. LM Studio was sitting on `:1234` with
`spark-x2.5-4b` (2.6 GB, already on disk) which returns a real
`get_time({"machine":"jetson"})` in 1.4 s. A working brain was invisible behind a broken
one.

Closed by asking Arya and doing what he chose: ollama stopped (the app is still installed),
LM Studio left serving the model that was already there. Nothing downloaded. The full gate
is green with no environment overrides, which is the point — a gate that needs a variable
set is a gate that describes the operator, not the machine.

What is left in BLOCKED.md: whether LM Studio is the Mac's permanent brain, and `brain.ts`
reporting the first server that *answers* rather than the first that can *call a tool*.
That second one is a product fix with its own slice, because `/brain` is what the app and
Needle's fallback read.
