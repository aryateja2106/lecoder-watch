Plan: write down why, before anything else

Before anyone designs or builds anything, the idea is written down in five plain headings: what hurts, what done looks like, who it touches, what must not change, and what is still open.

What the playbook says

  • Every idea is captured as an intent with five headings: Problem, Proposed outcome, Affected users and systems, Constraints, Open questions. (1)
  • The person with the idea drafts it with Claude; the product owner commits it. (1)
  • The committed intent is the one artifact that Stage 2 reads to write a spec. (1)
  • Measure the days from first conversation to committed intent, and how many intents survive. (1)
  • Humans own the intent; after release, problems found by monitoring come back as new intents. (6.1)

How you take part

  1. Talk. An agent interviews you, one question at a time, using intents/INTERVIEW.md. About 20 minutes per intent.
  2. Read the draft. Open the intent file the answers went into, under intents/. Check that the Problem is in your words and the outcome says what is true, not how it is built.
  3. Commit it, or tell the agent to. The commit is the record of who asked and when.
  4. Accept it. Only you change status: draft to status: accepted (intents/README.md). A spec may start only after that.

Interview me with the interview-me skill, one question at a time, and write intents/YYYY-MM-DD-<slug>.md from intents/TEMPLATE.md with status: draft. Do not mark it accepted.

For agents

Prove any change to intents/ with the shape check. A green run prints an ok line; a red one names the file and what is missing.

sh scripts/check-intents.sh
  • Never set status: accepted or status: closed. That is Arya's word (intents/README.md).
  • Findings from reviews, monitoring or security scans that need more than a one-file fix land here as status: draft with source: naming what found them.
  • When running the plans interview, follow intents/INTERVIEW.md: answers go under ## Decisions, and the five original headings are never renamed.
  • The trap: intent/ (singular) is test data for the product's on-device model. Playbook intents go in intents/ (plural) only. See the glossary entry.
  • Protected files this stage must not touch: AGENTS.md, CLAUDE.md, docs/factory/CHARTER.md, .factory/gates.conf, .claude/scripts/gates.sh.
  • Serialized files: none in intents/, but only Arya changes an intent's status.
  • Skills to load for an interview: interview-me, grill-with-docs, idea-refine.
