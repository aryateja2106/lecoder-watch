Six hand-offs, one product

Code is no longer the slow part. Deciding what to build, reviewing it and shipping it safely are. This site teaches that idea using our own repository as the worked example.

This week

Three moves. Each one is yours: no agent can make these for you. None of them needs any code.

  1. Put your ideas in your own words. Sit with an agent in the Claude Code desktop app, in a session opened on this repo. Tap the "Flush out my plans" chip, or say "Open intents/INTERVIEW.md and follow it". The agent interviews you from intents/INTERVIEW.md, one question at a time. The intents in intents/ dated 2026-09-27 are drafts an agent wrote for you. Only your "accepted" makes one real. Start with the design theme. About 20 minutes per intent, about an hour for the design sitting. B-06
  2. Turn on GitHub protection for main. About 2 minutes in GitHub → Settings → Rules, following the steps on the Ship page. After that, GitHub refuses any change to main that is not a pull request you merged yourself: no direct push, no force push, by anyone, including an agent using your account. B-04
  3. Decide what happens to the unreviewed Cursor pull requests. An unattended Cursor loop opened 119 pull requests on 22–23 September 2026 (123 open Cursor pull requests in all, counted on 2026-09-27). Close all, keep a few, or park them. Reply with the block id and your choice. B-15

The chain

Each stage ends by writing one thing down. The next stage starts by reading it. After a release, what we learn comes back as a new idea, so the chain is a loop.

  1. Intent, the why, in your words: intents/TEMPLATE.md
  2. Spec, what exactly gets built and how it looks: openspec/config.yaml
  3. Plan, the files that change and the proof, written before code: docs/factory/runs/README.md
  4. Pull request, a draft that a human merges, never an agent: docs/factory/CONTRACT.md
  5. Release, recorded with its date: PUBLISHED.md
  6. Findings, problems after release, written back as new intents: intents/README.md

How to read this site

Start with the product map, so you know what each folder is for. Then read the five stage pages in order, from Plan to Ship. Every stage page has the same parts, and the part called "How you take part" is yours.

Rules that outrank everything

These files win over anything on this site. They are linked, not copied, so they cannot drift.

  • ROADMAP.md, the non-goals: no cloud relay, no VNC, no account system. Only three things leave your machines: one anonymized daily heartbeat (you can switch it off), a problem report you choose to send, and push alerts, whose text is redacted before it goes to Apple's push service (APNs).
  • AGENTS.md, the rules for every agent, each one learned from a mistake that cost days.
  • CLAUDE.md, the non-negotiables: an agent never merges and never pushes main.
  • docs/factory/CHARTER.md, the rules for agents' freedom (the charter). It is still an unfilled template, so no agent may run on its own yet. B-16

How this site stays true

Every status line carries a proof: a file, a phrase in a file, or a question to GitHub. sh scripts/check-sdlc-status.sh goes red when a line disagrees with the repo, and names the exact word to change. The colours on this site are placeholders until you decide the design theme (B-06).

For agents

Read the state of every status line on every page from one command instead of parsing the HTML. It is printed by scripts/check-sdlc-status.sh.

sh scripts/check-sdlc-status.sh --board

Before editing this folder, read the folder brief docs/sdlc/AGENTS.md. Before committing, run both checks:

sh scripts/check-sdlc-status.sh
sh scripts/check-sdlc-site.sh

Block ids on this page come from docs/sdlc/BLOCKS.md. When you land a block, flip its line here in the same pull request.

Name trap: intent/ (singular) is test data for the on-device model. intents/ (plural) is Stage 1, Arya's ideas. Never mark an intent status: accepted on your own; that word is Arya's. When he types "I accept <title>" in the session, make that one edit and commit it.
