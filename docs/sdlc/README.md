# docs/sdlc — how LeSearch AI goes from idea to shipped

This folder is a small website that explains the AI-native software lifecycle (plan, design, build, test, deploy, maintain) using this repo's own files. Each page says what the playbook asks for, what our repo has today, the gap, the block of work that closes it, and what Arya does next. The work itself is one ordered list in [BLOCKS.md](BLOCKS.md). The reasoning behind the proposed layout is in [architecture-proposal.md](architecture-proposal.md), and five dated reviews of outside projects sit in [references/](references/orca.md) ([Orca](references/orca.md), [agent-git](references/agent-git.md), [Nethera](references/nethera.md), [OpenMuse](references/openmuse.md), [security-audit skill](references/security-audit-skill.md)).

Open [index.html](index.html) from a local clone (`open docs/sdlc/index.html`). GitHub shows `.html` files as source, not as pages, so read the site on the Mac. Read the pages in this order: [Lifecycle at a glance](index.html), [The product map](product.html), [Stage 1 · Plan](1-plan.html), [Stage 2 · Design](2-design.html), [Stage 3 · Build](3-build.html), [Stage 4 · Test](4-test.html), [Stages 5–6 · Ship](5-ship.html), [The ordered blocks](blocks.html), [Borrowed ideas](borrowed.html), [Words used here](glossary.html). All pages share one stylesheet, [sdlc.css](sdlc.css), and use no JavaScript.

It stays true in two ways. Every file a page names is a link, and `sh scripts/check-sdlc-site.sh` fails if any link points at a file that does not exist or if a block in `BLOCKS.md` is missing from the pages. The status chips (done, in progress, not started) are updated by hand in the same pull request that lands the work; each chip carries the proof it depends on. Agents: read [AGENTS.md](AGENTS.md) before editing anything here.
