Borrowed ideas

What we borrow from five other projects

We take ideas, not code. Anything that needs our server in the middle, an account, or VNC is refused, because our non-goals say so (ROADMAP.md, "Non-goals").

You named five projects to learn from. Each one was reviewed on its own on 2026-09-27, and each review ends with the one small piece of work worth taking from it. This page is the short version: one card per project, what we take, what we refuse and why, and the block that starts it. When someone says "Orca does X", look here first.

One line per project. Each line turns to done when that project's first piece of work has landed and its new check exists.

Orca

What it is
A free, open-source desktop app for running many coding agents side by side on one computer, each in its own copy of the project, with a phone app that watches them. It is the closest thing to what we do, built the other way round: the desktop is the product and the phone is an add-on.
We borrow
  • Each agent works in its own copy of the project (a worktree), so three agents on one repo cannot overwrite each other. Today they share one copy.
  • A separate key for each paired phone, so a lost phone can be cut off without re-pairing every device.
  • "We cannot reach that machine" is never shown as "the agent stopped". The screen should say "pair again" or "update needed", not just "offline".
We refuse, and why
Its cloud relay, sign-in and push service, and its SSH set-up: no cloud relay, no account system, and "no SSH" is our edge.
Licence
MIT. Borrowing a pattern needs no notice; a copied file keeps Orca's copyright line.
First block
None yet. The worktree idea is useful on one machine, not across machines, and ROADMAP.md lists per-agent isolation under "Later". So BLOCKS.md, "Deliberately not a block yet" keeps it until an intent asks for it. The "pair again, not offline" idea is the candidate for B-11 First multi-machine build block.

OpenMuse

What it is
A self-hosted personal-agent app from the CopilotKit team, still in alpha. It has a chat, a task list, and a queue of actions a person must approve before they happen.
We borrow
  • A written receipt for every approval: who answered, what, and when, one line each.
  • The answer applies only to the exact question the person saw, and can be used once.
  • A question left too long expires instead of being answered hours later.
We refuse, and why
CopilotKit's hosted service in the data path (no cloud relay), its Docker computer and Postgres database (local-first, native, light), and its access-key login (no account system).
Licence
MIT for the repo. CopilotKit's hosted service is not covered by it. The patterns are small, so we rewrite them rather than copy files.
First block
B-18 Approvals log that records what was chosen. Today, when you tap Allow, the daemon presses keys in the agent's terminal and writes nothing down, so you cannot show a client who approved what, or when.

Cloudflare security-audit-skill

What it is
Written instructions from Cloudflare that a coding agent follows to hunt for security holes. A second, independent agent then proves or rules out each finding, and the run leaves a written record.
We borrow
  • The whole method, installed as a skill exactly as published, pinned to one version, with our notes in a separate file.
  • A finding counts only after a second agent tries to disprove it.
  • Each fixed kind of hole becomes a new check, so it cannot come back quietly.
We refuse, and why
Committing audit results while this repo is public. An unfixed finding in git is a public disclosure, so results stay on your Mac until each one is fixed.
Licence
MIT. We keep Cloudflare's licence file next to the copied skill. The Cloudflare name goes in attribution only, never in our product copy.
First block
B-12 Security audit skill and first baseline. Today there is no recurring scan, no baseline, and no record of dismissed findings.

agent-git

What it is
A large Rust command-line tool that keeps agent conversations under version control, so they can be saved, shared with other people through its hosted website, and resumed. Our mesh sessions already keeps and resumes every conversation, without an account.
We borrow
  • A secret-masking step (redaction) that works on a live stream and cannot miss a secret cut in half between two pieces.
  • One shared reader for agent transcripts, instead of four modules each reading them their own way.
  • A clean way to ship a separate native helper program, if we ever need one.
We refuse, and why
Its hosted hub, its sign-in, and usage statistics that cannot be switched off: no account system, and nothing of yours leaves your machines except one anonymous daily heartbeat.
Licence
MIT. One file inside it comes from another project with its own terms, which were not checked.
First block
B-13 Streaming redaction for the live terminal. Today the live terminal is masked one piece at a time, in install/payload/meshd/pty.ts using install/payload/meshd/redact.ts. Whether a secret is ever actually split that way in real use is unverified.

Nethera

What it is
A service that runs apps on your own computer and gives them a public web address. Every visitor passes through Nethera's own servers first, which see the traffic and decide who gets in.
We borrow
  • An app is only ever reachable on a private address.
  • Every app link says in plain words who can open it.
  • Access keys are named, shown once, and can be revoked one by one.
We refuse, and why
Its servers in the traffic path and its login: no cloud relay, no account system.
Licence
MIT for the public part. Its security-critical servers are private, so there is nothing there to reuse.
First block
B-08 App link keys long enough to be unguessable. Today the secret in each app link is too short to share beyond your own devices. That is finding SEC-06 in docs/review-2026-09-17.md. This block makes links hard to guess. It does not yet decide who may edit an app's data; that is one of the intents in B-17.

A word on Rust

You asked how to bring TypeScript and Rust together. The agent-git review's answer is: not now. Nothing in the product has been measured as slow, and Rust would add a new toolchain and a separate build for every kind of machine.

When something is measured slow, Rust comes in as a separate helper program that the daemon talks to, never as code loaded inside the daemon. That is how the daemon already talks to the Mac's pointer-and-keyboard helper: install/payload/meshd/input.ts drives install/payload/bin/mesh-input.swift. If the helper crashes, the daemon keeps running and your phone keeps its machine.

  • The options, compared: references/agent-git.md, "Rust next to our Bun daemon: the options".
  • The same advice, applied to our modules: architecture-proposal.md, section 1.

The decision is yours. It is the third intent in B-17 The remaining three intents, which puts "no Rust yet" next to a real "yes" option: a first Rust helper program that you name.
