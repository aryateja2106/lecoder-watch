The product map

What we sell, and where it lives

"Use your Mac from your wrist." The product spec, docs/product/PRODUCT.md, names two loops, in this order:

  1. Reach your machines from anywhere: pointer, keyboard, screen, files, shell.
  2. Run agents 24/7 and answer them when they get stuck: the wrist buzzes, you answer in one tap.

The spec says the second loop is what sets us apart. This page shows each part a customer touches (a surface), the folder it lives in, and the command that proves it works.

Where we are

  • In progress The Mac app can be downloaded by customers (built, not yet distributed; your decision in PRODUCT.md §12) you checked 2026-09-27
  • Not started Strangers get the newest phone app from the public TestFlight link you B-05
  • In progress The installer never ships agent notes to users: the tarball is checked (scripts/check-payload-no-agent-docs.sh); the mesh upgrade --src copy does not drop them yet B-03 checked 2026-09-27

Each line is checked by sh scripts/check-sdlc-status.sh.

The surfaces

Seven things a customer touches, plus one they never see but everything depends on. Each card has the same four rows. "Prove it" gives a fast command first, then the slow one or the one that needs a device.

  • Apple Watch app and complication

    What it does for a customer
    Lists your machines, shows which agents are stuck waiting for you and lets you answer them, follow a live terminal, and move the Mac's pointer from the wrist. The watch-face complication shows how many agents are waiting without opening the app.
    Folder
    Watch/, WatchWidgets/ (the complication: WatchGlanceWidget.swift)
    Spec
    PRODUCT.md §7.2 Apple Watch
    Prove it
    Fast: ./.claude/scripts/gates.sh fast. Slow: MESH_SMOKE_REQUIRED=1 sh scripts/check-watch-smoke.sh (needs a watch simulator). The mic, the notification buttons and the crown can only be checked on your real watch (AGENTS.md, "What an agent cannot verify").

  • iPhone app and Lock Screen card

    What it does for a customer
    Pairs your machines, lists them, opens a terminal on any of them, controls a Mac's screen with your thumb, and sends a problem report. It also carries the watch's requests, and the Lock Screen card (a Live Activity) says "an agent is waiting on you".
    Folder
    iOS/ (iOS/INDEX.md), MeshWatchWidgets/, UITests/
    Spec
    PRODUCT.md §7.1 iPhone
    Prove it
    Fast: ./.claude/scripts/gates.sh fast. Slow: MESH_SMOKE_REQUIRED=1 sh scripts/check-ios-smoke.sh (opens the real app in a simulator and taps every tab).

  • The shared dictionary (phone, watch, widgets)

    What it does for a customer
    Customers never see it. It is the one set of words the phone, the watch, the Lock Screen card and the complication share, including the one piece of logic that decides which agent needs you right now. A mistake here shows up everywhere at once.
    Folder
    Shared/ (Shared/INDEX.md); the "who needs me" logic is sessionsNeedingAttention in Shared/Models.swift
    Spec
    PRODUCT.md §7.5 Shared
    Prove it
    Fast: ./.claude/scripts/gates.sh fast (its types gate compiles Shared/). Slow: sh scripts/check-all.sh.

  • Mac menu-bar app

    What it does for a customer
    A small dot at the top of the screen shows whether the LeSearch AI service is running on this Mac. One window asks macOS for the permissions the service needs; another shows the QR code your iPhone scans to pair.
    Folder
    MeshDesktop/ (the app starts in MeshDesktopApp.swift)
    Spec
    PRODUCT.md §7.3 Mac menu bar
    Prove it
    Fast: none. Slow: sh scripts/gate-build.sh (builds the apps with Xcode, takes minutes).

  • The daemon (meshd)

    What it does for a customer
    The small background program on each of your computers that the phone and watch actually talk to. It lists your agents, types into their terminals, controls the screen, sends alerts and keeps each agent conversation's history. Its front door is the most important security boundary in the product. (What "daemon" means.)
    Folder
    install/payload/meshd/ (INDEX.md). Key files: server.ts (every route), auth.ts (the front door), redact.ts (masks secrets before they leave the machine)
    Spec
    PRODUCT.md §5 The daemon
    Prove it
    Fast: sh scripts/check-host-guard.sh, sh scripts/check-redact.sh. Slow: sh scripts/check-mesh-auth.sh (starts throwaway daemons on spare ports).

  • The command line (mesh)

    What it does for a customer
    The tool you and your agents use on a machine to pair, check health (mesh doctor, mesh status), upgrade, rotate a leaked key and uninstall cleanly. (What mesh means.)
    Folder
    install/payload/bin/; the tool itself is install/payload/bin/mesh
    Spec
    PRODUCT.md §6 The command line
    Prove it
    Fast: sh scripts/check-mesh-upgrade.sh. Slow: mesh doctor on a real machine.

  • Installer

    What it does for a customer
    One pasted command puts the daemon, the mesh tool and the agent alert helpers into ~/.mesh, starts them at boot, and ends by showing the pairing QR code. What customers run is whatever was last published, so the release path is the main risk here.
    Folder
    install/; the script is install/install.sh, packed by scripts/package-mesh-install.sh
    Spec
    PRODUCT.md §3 Surfaces and the install contract
    Prove it
    Fast: sh scripts/check-package-mesh-install.sh. Slow: sh scripts/check-install-idempotent.sh.

  • Landing site

    What it does for a customer
    The public website: what the product is, and the install command. Its checks pass today, but every deploy is done by hand.
    Folder
    web/; the page is web/index.html
    Spec
    PRODUCT.md §3 (its live address is listed there)
    Prove it
    Fast: sh scripts/check-links.sh, sh scripts/check-brand.sh. Slow: MESH_PUBLISHED=1 sh scripts/check-published.sh (live; this is the finish line for a release).

The one command for everything

One command answers "is the product still healthy?" in under a minute, with no phone and no simulator. It is the fast level of the gate, .claude/scripts/gates.sh.

./.claude/scripts/gates.sh fast

Healthy output, seen 2026-09-27:

FACTORY_GATES: level=fast status=GREEN passed=2 failed=0 failing=none skipped=none misconfigured=none

full takes minutes and a simulator, so it runs before a pull request, not while an agent is working.

Behind the scenes

Things customers never see, but that keep the product honest:

  • scripts/INDEX.md: the self-checks, each written after something real broke. Count them yourself: find scripts -maxdepth 1 -name 'check-*' | wc -l
  • docs/agents/CHECKS.md: what each check proves, in one line each (generated).
  • docs/agents/UI-MAP.md: every screen on the iPhone and the watch, and where it lives.
  • docs/agents/CODEMAP.md: the map of the code that agents read first (generated).
  • install/payload/meshd/telemetry.ts: the one anonymous heartbeat a day, which you can switch off. Only three things leave your machines: that heartbeat, a problem report you choose to send, and push alerts, whose text is redacted before it goes to Apple's push service (APNs).
  • scripts/feedback-to-issues.ts: problem reports sent from the app become GitHub issues.
  • index.md: the agents' start page.

Two folders with almost the same name

intent/ (singular) is test data for the small on-device model that turns a phrase like "tell claude yes" into an action.

intents/ (plural) is where new ideas are written down. That is Stage 1, Plan.

How you take part

Two decisions about the surfaces are yours alone. Both are listed in docs/product/PRODUCT.md §12 Open decisions.

  1. How the Mac app reaches customers. The spec lists the options. It is a choice, not a build; once you pick, an agent does the work.
  2. Submit the newest TestFlight build for Beta App Review, so the public link stops serving the August build. Small in your time, plus Apple's review wait. Details and the two choices inside it are in B-05.

Show me the watch app working: run MESH_SMOKE_REQUIRED=1 sh scripts/check-watch-smoke.sh, which launches it on a watch simulator, and paste the last lines. A build alone does not count. Do not touch the live daemon on port 8899.

For agents

Four files are serialized: one agent at a time (AGENTS.md, "Must be serialized"):

  • Shared/Models.swift
  • Shared/MeshClient.swift
  • install/payload/meshd/server.ts
  • project.yml

docs/product/PRODUCT.md must change in the same pull request as a new screen, daemon module, mesh verb or capability (PRODUCT.md §0).

Daemon tests run on a throwaway port. Never restart or redeploy the live daemon on :8899; the owner's phone is paired to it.

./.claude/scripts/gates.sh fast
sh scripts/check-product-spec.sh
sh scripts/check-sdlc-status.sh
