Test: one command says yes or no

Before you look at anything, the agent checks its own work with one command. A yes only counts when the change was actually run, not just built.

What the playbook says

  • The agent checks its own work before a person sees it (4).
  • One command wraps all the checking, and its healthy output is written in CLAUDE.md under "Verifying your work" (4).
  • A bug fix starts with a test that fails. The agent may not edit that test to make it pass (4).
  • A change to a screen gets a visual check, not just a passing build (4).
  • Run 20 to 50 real tasks as evals in CI, on every change to the agents' rules and every night (4.1).
  • Every problem found after release becomes a permanent eval (4.1).

The gap

  • The healthy output is not written in CLAUDE.md, so an agent cannot tell a good run from a bad one without guessing.
  • deep can never be green: npm audit fails with ENOLOCK because there is no lockfile, and its architecture rule is empty.
  • The full run quietly needs the Pi, the Jetson and the local model servers. The only way to skip them is MESH_OVERNIGHT_SKIP in scripts/check-overnight.sh, and CLAUDE.md does not mention it.
  • On 2026-09-27 three self-checks were red, so full started red, and CI was red on the newest integration branch (cause unverified).
  • No suite tests the coding agents themselves (evals/cases.jsonl).

Blocks that close it

Agent evals in CI are deliberately not a block yet. A real eval runs an agent and pays for model calls, so it waits until agents run unattended on a green CI (later, and why).

How you take part

  1. Pick the way out for the deep gate. One word in chat, about 2 minutes: add a lockfile, point the audit at the daemon's real dependencies, or drop the gate. The agent records your pick in docs/factory/DECISIONS.md (B-20).
  2. Pick the CI fix and read the diff. After an agent writes down why the iPhone build fails, you choose the option and read the change to .github/workflows/ci.yml. About 10 minutes (B-19).
  3. Do the checks only your devices can do. The watch mic, the buttons on a notification, the crown. Agents cannot drive your real iPhone or watch (AGENTS.md). A few minutes per change that touches them.
  4. When an agent says "done", ask for the pasted gate line. No line, not done. A RED or MISCONFIGURED line is also not done. Ten seconds.

Run ./.claude/scripts/gates.sh fast and paste the FACTORY_GATES line exactly. Then hand the change to the factory-verifier agent; you may not grade your own work.

A worked example from our own history

In August 2026, version 0.5.0 shipped an iPhone app that crashed on any screen with a text box. It compiled, and it passed every check that reads source code. Only running the app and putting a text field on screen could catch it.

UITests/SmokeTests.swift exists because of it; its header comment tells the story. The lesson became rule 1 in AGENTS.md: "verify by running, not by building". That is why a green build alone is never a yes here.

A bug fix starts with a failing check. Prove it fails without the fix:

./.factory/scripts/prove-test.sh <base-ref> --test-path <path> -- <test command...>
