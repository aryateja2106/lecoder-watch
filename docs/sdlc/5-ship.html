What the playbook says

(Numbers in brackets are the playbook's section numbers.)

Stage 5 · Deploy

  • A written REVIEW.md tells the reviewer what matters, and an agent never approves its own code (5.1).
  • Risky actions pass an approval gate that a person controls, and every decision is logged (5.2).
  • Agent work in CI starts read-only, every agent write arrives as a pull request, and rollback is one rehearsed command (5.3).

Stage 6 · Maintain

  • Watch one number with a known normal range, and turn anything outside it into a new intent (6.1).
  • Scan for security holes on a schedule, check every finding, and write a reason for every dismissal (6.2).
  • Answer problems in a chat channel that doubles as the record, and write lessons to one file (6.3).

Stage 6 · Maintain: a normal band for one number

A control band is the normal range of one number, worked out from its own history. σ (sigma) is how far a reading is from normal: 1σ is a small wobble, 3σ is rare. Each step up allows the agent a bigger action, from writing a note, to reading logs, to proposing a fix or a runbook step.

The playbook's template

# bands.yaml
metric: ci_test_failure_rate
baseline: rolling_30d
rules: western_electric
tiers:
  1sigma: { action: log }
  2sigma: { action: diagnose, tools: "Read,Grep,Bash(gh run view *)" }
  3sigma: { action: propose, routes: [pull_request, runbook:rollback-deploy] }

Two side rules

  • One source of truth per kind of document. For each kind (intent, spec, plan, queue, release state, your to-do list) one file or place wins, and the rest are history. Today index.md has no such table, and docs/README.md still points at older pages. B-22 fixes this.

How you take part

  1. Turn on the ruleset yourself. An agent must not change account settings. On github.com: the repo, then Settings, Rules, Rulesets, New branch ruleset. Target main only. Tick "Require a pull request before merging", leave "Required approvals" at 0 (you are the only reviewer, and GitHub never lets the author of a pull request approve it, so a required approval would block every merge; the review is you reading the pull request and clicking merge). Tick "Block force pushes" and "Restrict deletions", and leave the bypass list empty. About 2 minutes (B-04).
  2. Decide the Cursor pile. Close all, keep a few, or park them in one tracking issue. One decision, written in docs/factory/DECISIONS.md. The pull requests are stacked on each other, so any clean-up goes from the leaves up. An agent closes them only after your yes in chat, typed in the Claude Code desktop app in a session opened on this repo (B-15).
  3. You merge, never an agent. Every change arrives as a draft pull request. Read it, then merge it yourself.
  4. Say yes before anything public. A release, a TestFlight upload or closing a pull request needs your yes typed in chat (B-14, B-05).
  5. Triage each finding. Once the security audit runs, each finding gets one of three answers: fix now, schedule it as an intent, or dismiss it with a one-line reason. The findings stay on your Mac, never in git (B-12).

Open a draft pull request and stop. Do not merge it, and do not close or merge any other pull request without my yes in this chat.

A worked example from our own history

The finish line went green

PUBLISHED.md and scripts/check-published.sh answer one question: are we really live for strangers, or did we only build it? On 2026-09-23 the full gate recorded in the ledger went green at commit c6823f2, with no environment overrides. The line it recorded:

FACTORY_GATES: level=full status=GREEN passed=4 failed=0 failing=none skipped=none misconfigured=none

That is Stage 5 working: a release, a proof that it is live, and a written ledger a checker reads back.

The rule nobody enforced

"An agent can never merge" lives in CLAUDE.md and is enforced only by .claude/hooks/block-merge.sh, a script on this Mac. Cursor's cloud agents never run it. An unattended Cursor loop opened 119 pull requests on 22–23 September 2026 (123 open Cursor pull requests in all, 112 of them stacked on each other, counted on 2026-09-27). The charter says to stop at more than 3 waiting items (docs/factory/CHARTER.md), but nothing enforced it. On 2026-09-27 main still had no GitHub protection, so the only thing between that pile and customers was that nobody pressed merge.
